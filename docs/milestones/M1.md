## Step 1: rules (game/domain)

| File | Rule |
| --- | --- |
| `phenotype.gd` | The one stat calculation. Benefits diminish per extra copy (copies ranked largest first, so part order never matters); upkeep and mass are paid in full and scale with size; mass slows speed and acceleration; stats are capped. Keeps mouth and spike angles, and each spike's own damage, for facing checks. |
| `actor_state.gd` | Health and energy. Upkeep and movement drain energy; at zero the cell moves at half speed and loses health, and food ends it. Health regenerates above half energy. |
| `interaction_resolver.gd` | Feed, bite and ram: diet, reach, facing arc, size limit and cooldown. Only spikes facing the target count in a ram (strongest first, then diminishing); backing away is no ram; nothing can bite or ram itself. Damage includes the target's defense, applied once. A refusal names the missing requirement and changes nothing. |
| `ecology_region.gd` | Plankton zones with capacity and logistic regrowth plus a floor, so an empty zone always recovers. Seeded spawn points. Niche caps by role. |
| `editor_session.gd` | Working copy with undo, redo, mirror, move, scale; cost of additions minus refunds; preview equals commit; a failed commit keeps the original body and points. |
| `lineage.gd` | Found a lineage from a starting body (grazer, hunter, omnivore); reproduction needs 70% energy and a session opened with the save's current points, and records generation n+1; death keeps the body and loses a quarter of unspent points; points are earned from food and one per 30 s alive. |
| `save_game.gd` + `systems/save_migrations.gd` | Save schema v2 adds adaptation points; v1 saves migrate in memory. A missing or wrong-typed field in a save (`json_values.gd`) fails validation, so the backup is used and is not overwritten by the damaged file. |

All numbers are PROPOSED tuning (`game/data/part_catalog.json` and the constants at the top of each file).

### Checks run (2026-10-22, Linux container)
- `tests/run_tests.gd`: 90 tests, 0 failed. Deliberately breaking the death rule, the ram direction rule or the stale-session rule makes a test fail.
- Boot smoke check: four PASS lines.
- An independent review (four reviewers, each finding re-checked by a skeptic) confirmed 8 rule bugs and 15 test gaps; all are fixed and covered by tests in this PR. A second review of those fixes found 6 more edge cases (wrong-typed save fields loading as empty, part id reuse, infinite zone values, two runner gaps); also fixed.
- The test runner fails a test that hits a script error, a test method that takes arguments, a file that fails to parse, and a file that does not extend `TestCase`, instead of passing or hanging. Persistence tests use a per-process folder and remove folders left by killed runs.
